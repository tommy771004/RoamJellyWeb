# Async Feedback 非同步回饋規格

RoamJelly 的 AI 生成、共編同步、儲存、匯入與分帳都可能延遲或失敗。回饋的目標是讓使用者知道系統正在做什麼、資料是否安全、下一步如何恢復。

## 狀態模型

| 狀態 | 必要回饋 |
| --- | --- |
| Loading | 保留原內容與主要操作脈絡，顯示正在處理的工作 |
| Success | 就地更新結果；短暫 Toast 僅作補充 |
| Offline | 清楚表示本機／待同步狀態，不假裝已送出 |
| Conflict／Lock | 顯示誰正在編輯、何處被鎖定與可採取動作 |
| Error | 保留輸入與選擇，說明問題、提供精確重試或替代方案 |

## 規則

- 表單錯誤放在欄位或提交區附近；Toast 不能成為唯一錯誤載體。
- AI 生成中可取消或返回時，說明草稿是否保留；生成失敗時保留 prompt 和偏好。
- 同步狀態不可只用顏色、旋轉圖示或短動畫；附加文字與可存取 live region。
- 非同步請求必須避免舊回應覆蓋新操作；重試不可重複建立旅程、節點或交易。
- Skeleton 僅在版面已知且時間短暫時使用；長任務需要具體進度或可理解的等待文案。

## 驗收

驗證 AI 產生、景點更新、拖曳重排、共編鎖定、離線恢復、圖片搜尋、分帳送出與 API 失敗；每一流程測試重試、焦點、live region 與資料保留。
