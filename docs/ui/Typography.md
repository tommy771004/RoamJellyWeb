# Typography 字體與文字層級規格

RoamJelly 的文字系統服務旅遊決策與旅途中快速操作：先看懂「哪一天、去哪裡、何時、和誰、花多少」，再閱讀 AI 建議與延伸內容。品牌的柔和感可以存在，但不得壓過可掃讀的行程資訊。

本文件是目標規格；既有 Tailwind class 與字體使用仍需逐頁遷移與驗證。

## 字體方向

- 介面優先使用可完整覆蓋繁中、日文、韓文與拉丁文字的 system stack；品牌字體必須先完成授權、載入效能與多語系回歸。
- 不以 mono 當作 UI 的預設語氣；時間、日期與金額使用 `font-variant-numeric: tabular-nums lining-nums` 對齊。
- 不以全大寫、過大字距或 10px eyebrow 承載主要資訊；CJK 文案使用自然句式。

## 語意樣式

| 樣式 | 行動版 | 用途 |
| --- | --- | --- |
| `app-title` | 24/30px，650–750 | 首頁、旅程與工具頁標題 |
| `trip-title` | 20/26px，650–750 | 行程名稱、旅程卡主標 |
| `day-title` | 18/24px，600–700 | 第幾天、日期群組 |
| `spot-title` | 16/22px，600–700 | 景點、航班與清單項目 |
| `time-value` | 20/24px，650–750 | 出發／抵達、行程時間；使用 tabular numerals |
| `body` | 16/24px，400–500 | 說明、AI 建議、可編輯內容 |
| `label` | 14/20px，500–650 | 欄位、按鈕、短狀態 |
| `meta` | 12/17px，400–550 | 地點、最後同步、協作者與幣別 |

- 同一畫面以 4 至 6 個層級建立節奏；不要以全面粗體或彩色 badge 補救層級。
- 主要景點、錯誤、同步衝突與費用不可使用 `meta` 或被 line clamp 隱藏。
- 行動版 input、select、textarea 的文字至少 16px，避免聚焦自動放大。

## 資訊優先順序

### 行程畫面

1. 日期、當日摘要與目前檢視。
2. 時間、景點名稱、位置與重要移動資訊。
3. 協作鎖定、離線／同步、衝突與未儲存狀態。
4. 備註、AI 建議、圖片與次要 metadata。

### 分帳與工具

1. 金額、幣別、代墊人與分攤對象。
2. 交易名稱、所屬景點／日期與結算結果。
3. 補充說明與建立時間。

## 響應式、在地化與驗收

- 320px、200% zoom、長景點名與 EN／zh-TW／ja／ko 的文字都要自然換行，不遮住底部導航或主要操作。
- 日期、時間、貨幣與人數一律由 locale formatter 顯示；畫面值與 API 值分離。
- 逐頁檢查 light、dark、強制色彩模式、字級調整與字體載入失敗的可讀性。
